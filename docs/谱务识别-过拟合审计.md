## 3. 看着像特例、其实是普遍判据（**别误删**）

这一节是给后人看的：下面这些都是**有意为之**的普遍设计，撤掉会立刻变差。

1. **`decideTitleCrop` 的三个不裁分支（`no-staff` / `too-tall` / `too-thin`）都是安全降级** ——
   不裁 = 退回整页 = 改动前行为。这是「**不确定就不做决定，由人兜底**」的直接实现。
2. **用「行内最长连续暗段」而不是「行墨量」**（`staff-line.ts:33`）——
   第一版用行墨量 + 全页最大值定阈值，实测 47% 的裁切把谱线带进送检图；
   换成绝对量后问题消失。**特征选对是因为它抓住了谱线的本质**（一条横贯谱表的长横线），
   不是因为在语料上跑得好。
3. **`MIN_LINES = 5` + `CONFIRM_MIN_LINES = 3` + 间距带** —— 乐理定义与结构约束，
   换任何出版社都成立。它不是「语料的形状」，是**乐谱的形状**。
4. **`mapLinesToPages` 的两条弃权判据**（`mosaic.ts:140-142`）——
   防的是「看起来完全合法的错答案」（文字归到错页 / 全归第 1 页而 `success`、`pageCount`
   全是正常的）。与版式无关。
5. **`composeMosaic` 的等高断言 + 组内 `bandHeight` 作除数**（`segmentation-run.ts:54-57` / `:80-84`）——
   同一类防静默错答案。
6. **全部平台契约型常量**：`MOSAIC_BUDGET_BYTES`、`MOSAIC_HARD_LIMIT_BYTES`、
   `OCR_TARGET_LONGEST_SIDE`、`OCR_MAX_SCALE`、`OCR_TIMEOUT_MS`、`LLM_TIMEOUT_MS`。
   它们的依据是**外部限额与下游预算**，不是语料。
7. **`unsafe-name.ts` 的 `/` 刻意不收** —— #12 明确允许「木琴/钟琴」这种合称，
   是**语义**不是疏漏。
8. **`renderPagesForAnalysis` 把「空白顺延」与「读了没结论就换下一页」合成同一个循环**
   （`pdf-render.ts:239`）—— 两者都是「这一页不算数」。合成一个循环是这个设计的**要点**，
   不是简化。
9. **`segmentation.ts` 的 `normalizeSegments` 语义是 filter，而 `moveSegmentStart`
   是「拒绝而不是丢弃」**（`segmentation.ts:98-101`）—— 拿 filter 直接接输入框的中间态，
   敲一个字符就会把边界合并掉，一段消失、只能重跑（再烧 N 次 OCR）。
   这是**交互语义**，不是代码风格。
10. **`upload-modal.tsx` 拆段后不按位置预填号** —— 旧启发式已在语料上被证伪
    （`Piccolo,_Flute_1,_2.pdf` 会把每段都填成 `[1,2]`）。**别再加回来**。
11. **`analysis.ts:164-165` 的 `evidence` / `evidenceFound` 用 `typeof` 判型而不是 `??`** ——
    「没这个字段」与「模型没给（空串）」在界面上**不等价**，那是产品语义。
    **这不是兼容层，别顺手改成 `?? ""`**。
12. **`subPartsOverCap` 整条链路**（`sub-parts.ts:159` / `analysis.ts:150` /
    `overSubPartsCap`）—— 注释写「今天不可达」，但它防的是**两仓常量漂移**（未来），
    不是版本差。删掉它，「后端调大上界 ⇒ 前端静默吞号」就重新变成静默路径。
13. **`sectionRaw` 的 `typeof` 判型与 `sectionWarning`** ——
    ⚠️ 旧笔记（2026-10-16 记的「前端 0 引用、该删」）**已过期**：现在
    `analysis.ts:146` 写、`upload-modal.tsx` 落行、`row-text.ts` 的 `sectionWarning` 读，
    它是「两仓声部词表漂移」的**唯一可见信号**。**按新代码判，不要按旧笔记删**。
14. **前端那几处「旧版就是降级到…」的注释** —— 那是**行为说明**（讲为什么这样分工），
    不是兼容代码，只是措辞里带「旧版」。

## 4. 我们已知、但当前不打算动

1. **`findFirstStaffLine` 对亚度级倾斜敏感** —— 2px 粗的线每 ~366px 漂 1px 就断成
   <594px（阈值），跳过第一谱表、latch 到后面某组。**已记为 pkuso-web#385**，
   是「图像候选召回率」的前提。**本次不动**（属输入侧，用户在 #96 第 2 批已归位）。
2. **用固定阈值（`staffPct`）判分谱页边界** —— **已实测证伪**（换出版社后 11 份错 9 份），

   而真信号是图像内容。
3. **图像特征单独当判据** —— 已实测证伪（精确率 0.83 / 0.54 / 0.75），
   **只能当召回，不能当判据**。原理上：判据要分的是「顶部那块大字是不是标题」，
   而速度记号 / 乐章标题与标题在像素上是同一类东西。
4. **总谱的本地判据** —— 三个（`staffPct` 阈值 / 顶部墨量 / 每系统谱表数）**全败**，

5. **改 prompt 措辞** —— #96 已决定不再立项，**除非先给出「为什么这一版会不一样」的

6. **窄带高度** —— 已由 `band-height.ts` 的文档自适应取代（本 PR，backend#96）：

   **输入侧**（前端补第 1 页）；分段判据与 prompt 未动。
7. **`MAX_PAGES_EXAMINED`** —— 默认关的升级链，改值等于改配额，

8. **`MOSAIC_TYPICAL_BAND_BYTES`** —— 只影响界面上的估算数字，且当前**宁可高报**。
9. **`MAX_SUB_PARTS` / `MAX_EXTRA_SECTIONS` 的跨仓常量漂移** —— 两个方向都已有可见信号
   （`overSubPartsCap` / `sectionWarning`），但两仓之间**没有机制能自动发现漂移**，
